# Frontend Design Guide — Premium Construction & Engineering Website

## 1. Design Objective

Create a premium, modern construction and engineering website that feels:

- Precise
- Technical
- Confident
- Architectural
- Industrial
- High-value
- Trustworthy
- Editorial rather than template-driven

The website should feel **engineered, not decorated**.

The visual reference point is:

> **Engineering precision × architecture studio × industrial strength**

Do **not** imitate generic construction websites or AI-generated SaaS landing pages.

---

## 2. Core Design Principle

The site should communicate capability through:

- Strong typography
- Disciplined spacing
- Structural grid systems
- Large project imagery
- Technical drawings
- Restrained motion
- Clear hierarchy
- High-quality case studies

Avoid filling the interface with decorative UI components.

Every element should have a purpose.

---

## 3. Brand Personality

The brand should feel:

**Solid / Precise / Controlled / Premium / Dependable**

It should look suitable for:

- Major contractors
- Engineering consultancies
- Structural engineering firms
- MEP firms
- Infrastructure companies
- Technical design companies
- Construction management firms
- BIM and detailing companies

The design must work across:

- Website
- Project proposals
- Technical reports
- Drawing covers
- Site hoardings
- Vehicles
- Helmets
- Business cards
- Social media
- Presentation decks

---

## 4. Visual Direction

Use a **Precision Industrial + Editorial** design system.

Think of the website more like an architectural publication than a typical corporate landing page.

### Recommended visual characteristics

- Large editorial headlines
- Strong geometric alignment
- Full-width or full-bleed photography
- Technical annotations
- Generous whitespace
- Thin structural lines
- Large project numbering
- Monospaced technical labels
- Asymmetric but disciplined layouts
- High contrast between imagery and text
- Restrained use of accent colors

Do not make every section look identical.

Sections should feel compositionally different while still belonging to the same design system.

---

## 5. Color System

### Primary Palette

| Role | Color | Hex |
|---|---|---|
| Graphite | Almost black | `#171918` |
| Warm Concrete | Light neutral | `#D9D5CC` |
| Off White | Main light background | `#F4F2ED` |
| Steel Grey | Secondary text / lines | `#777B7A` |
| Burnt Orange | Accent | `#C86432` |

### Usage

Use approximately:

- 50–60% off-white / neutral backgrounds
- 25–35% graphite / dark surfaces
- 10–15% steel / muted neutral elements
- 5–10% accent color

The accent color must feel intentional.

Do not flood the interface with orange.

### Avoid

- Bright construction yellow everywhere
- Generic royal blue + orange combinations
- Purple gradients
- Neon colors
- Blue SaaS gradients
- Excessive multicolor sections

---

## 6. Typography

Typography should carry much of the visual identity.

### Primary Typeface

Use a clean modern grotesk / sans-serif such as:

- Instrument Sans
- Inter
- Manrope
- Geist
- Neue Montreal-style alternatives

### Technical Typeface

Use a monospaced font for:

- Project metadata
- Drawing references
- Section labels
- Coordinates
- Dates
- Numbers
- Technical annotations

Recommended:

- IBM Plex Mono
- Geist Mono
- JetBrains Mono

### Typography Style

Large headlines should be bold, concise, and architectural.

Example:

```text
BUILDING WITH
PRECISION.
```

Supporting technical labels:

```text
PROJECT / 024
ABU DHABI, UAE
STRUCTURAL ENGINEERING
2026
```

### Typography Rules

- Avoid overly rounded fonts
- Avoid excessive font weights
- Use strong scale differences
- Keep body text highly readable
- Use uppercase sparingly for technical labels
- Keep technical text compact
- Avoid giant paragraphs
- Prefer short, confident statements

---

## 7. Grid & Layout System

Use a disciplined editorial grid.

### Desktop

Recommended:

- 12-column grid
- Large outer margins
- Strong vertical rhythm
- Wide image areas
- Occasional intentional asymmetry

### Tablet

- 8-column grid

### Mobile

- 4-column grid

### Layout Principles

- Align text, images, numbers, and metadata precisely
- Use whitespace as a design element
- Let important project imagery dominate
- Do not force all content into centered containers
- Avoid repetitive 3-column card grids
- Use large horizontal compositions when possible

---

- Internal group spacing: `32–48px`

Avoid cramped content.

# 10. Hero Section

The hero should be visually dominant.

### Recommended structure

```text
[ FULL-SCREEN PROJECT IMAGE / VIDEO ]

ENGINEERING
WHAT ENDURES.

Structural engineering and construction
solutions across the UAE.

Explore Projects →
```

### Hero Guidelines

- Use one excellent visual
- Keep messaging short
- Avoid multiple CTA buttons
- Avoid floating cards
- Avoid decorative blobs
- Avoid unnecessary metrics overlaid everywhere
- Prefer real construction / engineering imagery
- Add subtle technical overlays only if they strengthen the identity

Optional technical elements:

```text
GRID B4
+24.750
SECTION 04
1:100
```

Use these sparingly.

---

# 11. Services / Capabilities

Do not present services as six generic rounded cards.

### Better approaches

Use:

- Large horizontal service rows
- Numbered capabilities
- Split-screen layouts
- Expandable editorial lists
- Image + service combinations
- Large typographic sections

Example:

```text
01
STRUCTURAL ENGINEERING
Design, analysis and technical coordination for complex structures.

02
BIM & DETAILING
Coordinated models, fabrication drawings and multidisciplinary workflows.

03
CONSTRUCTION SUPPORT
Technical support across design development and execution.
```

### Interaction

On hover or focus:

- Reveal supporting image
- Change technical diagram
- Show concise description
- Animate a structural line

Keep motion subtle.

---

# 15. Imagery

Use:

- Real construction photography
- Architecture photography
- Structural details
- Site execution
- Steel / concrete details
- Engineering drawings
- BIM models
- CAD drawings
- Material close-ups
- Site teams where relevant

### Image treatment

Prefer:

- Large images
- High resolution
- Strong crops
- Muted grading
- Natural contrast
- Minimal filters

Avoid:

- Generic stock workers smiling at camera
- AI-generated construction workers
- Fake skyscraper renders
- Overprocessed HDR images
- Excessively saturated imagery

---

# 16. Motion & Interaction

Animation should communicate precision and progression.

Recommended:

- Masked image reveals
- Text reveal on scroll
- Thin line drawing animation
- Subtle parallax
- Project number transitions
- Smooth image scaling
- Technical annotation reveals
- Controlled page transitions

Use:

- Motion / Framer Motion for most interactions
- GSAP only when advanced scroll choreography is genuinely required

### Animation rule

If removing an animation makes the website clearer, remove it.

### Avoid

- Constant floating objects
- Excessive scroll-jacking
- Bouncy animations
- Cursor gimmicks
- Spinning icons
- Overly dramatic text entrances
- Animation on every element

---

# 17. Navigation

Keep navigation minimal and confident.

Example:

```text
Projects
Capabilities
About
Insights
Contact
```

Optional right-side CTA:

```text
START A PROJECT →
```

### Header behavior

- Transparent over hero
- Becomes solid on scroll
- Simple mobile drawer
- Avoid huge mega menus unless genuinely needed

---

# 18. Buttons & Links

Buttons should feel architectural, not app-like.

Prefer:

```text
VIEW PROJECT →
EXPLORE CAPABILITIES →
START A PROJECT →
```

Use:

- Text links with arrows
- Thin outlined buttons
- Sharp or minimally rounded corners

Avoid:

- Giant pill buttons
- Gradient buttons
- Glowing buttons
- Excessive rounded corners

---

# 19. Corners & Shapes

Default to:

```text
border-radius: 0–8px
```

Not everything needs rounded corners.

Images can often remain square-edged.

### Avoid

- `20px+` radius on everything
- Pill-shaped containers everywhere
- Floating rounded dashboard panels
- Nested rounded cards

---

# 20. Borders & Lines

Thin structural lines are encouraged.

Use:

```text
1px solid rgba(...)
```

for:

- Section divisions
- Technical grids
- Metadata
- Navigation separation
- Project indexing

Lines should strengthen alignment and structure.

---

# 21. Icons

Use icons minimally.

Recommended:

- Lucide icons
- Simple custom line icons
- Technical symbols where appropriate

Avoid adding an icon to every heading.

For many sections, typography alone is stronger.

---

---

# 26. Responsive Design

Mobile must feel deliberately designed, not compressed desktop.

### Mobile rules

- Keep typography bold but controlled
- Reduce decorative technical overlays
- Keep images dominant
- Stack project metadata intelligently
- Avoid horizontal overflow
- Maintain strong spacing
- Simplify motion
- Keep tap targets accessible

Test at least:

```text
375px
430px
768px
1024px
1440px
1920px
```

---

# 27. Accessibility

Minimum requirements:

- WCAG AA color contrast
- Semantic HTML
- Keyboard navigation
- Visible focus states
- Proper labels
- Alt text for meaningful images
- Reduced motion support
- Correct heading hierarchy
- Accessible mobile navigation

Do not sacrifice accessibility for visual effects.

---

# 28. Performance

Target:

- Lighthouse Performance: 90+
- Accessibility: 95+
- Best Practices: 95+
- SEO: 95+

Use:

- Next.js Image
- AVIF / WebP
- Responsive image sizes
- Lazy loading
- Font subsetting
- Minimal client-side JavaScript
- Server Components where appropriate

Do not autoplay massive unoptimized videos.

# 31. Anti-Slop Rules

The following are prohibited unless there is a clear reason:

- Purple-blue gradients
- Glassmorphism
- Random gradient blobs
- Floating decorative spheres
- Excessive cards
- Every section inside a rounded box
- Giant pill buttons
- Generic icon grids
- Fake testimonials
- Random dashboard widgets
- Neon glows
- Excessive shadows
- Unnecessary badges
- Repetitive three-column layouts
- Generic AI illustrations
- Stock SaaS copy
- Overuse of centered layouts
- Random animated counters
- Excessive scrolling effects
- Decorative elements without brand relevance

Do not make the site look like an AI-generated template.

---

# 32. Copywriting Style

Use concise, confident language.

### Good

```text
ENGINEERING WHAT ENDURES.

Precision from concept to construction.

Complex structures.
Clear solutions.
```

### Avoid

```text
We are passionate about delivering innovative
world-class solutions tailored to every client's
unique needs.
```

Avoid empty corporate language.

Prefer:

- Specific claims
- Real capabilities
- Measurable outcomes
- Technical credibility

# 33. Design Review Checklist

Before considering a page complete, ask:

### Brand

- Does this look like a premium engineering company?
- Could this design belong to another random SaaS company?
- Are engineering and construction visible in the visual language?

### Layout

- Is the grid disciplined?
- Is there enough whitespace?
- Does each section have a distinct composition?
- Are project images large enough?

### Typography

- Is the hierarchy obvious?
- Are headlines concise?
- Is technical typography used consistently?

### UI

- Are there unnecessary cards?
- Are there unnecessary rounded corners?
- Are icons overused?
- Is the accent color restrained?

### Motion

- Does every animation serve a purpose?
- Is scrolling comfortable?
- Does reduced-motion mode work?

### Mobile

- Does the page feel designed specifically for mobile?
- Is content still readable and visually strong?
- Are interactions touch-friendly?

### Performance

- Are images optimized?
- Is unnecessary JavaScript removed?
- Are videos compressed and lazy-loaded?

# 34. Codex / AI Implementation Instruction

Use this instruction when building or redesigning the website:

```text
Build a production-quality construction and engineering website using
Next.js, TypeScript and Tailwind CSS.

The website should feel like a premium contemporary engineering consultancy
or European architecture studio rather than a generic corporate or SaaS
template.

Design direction:
Precision Industrial + Editorial.

Prioritize strong typography, disciplined grid systems, substantial
whitespace, technical drawings, full-bleed project photography and
restrained purposeful motion.

Use engineering geometry, structural grids, drawing annotations, project
numbers and technical metadata as recurring brand elements.

Avoid stereotypical AI-generated website aesthetics:
- no excessive rounded cards
- no purple/blue gradients
- no gradient blobs
- no glassmorphism
- no generic icon grids
- no excessive pills
- no unnecessary shadows
- no random floating objects
- no repetitive card layouts
- no generic SaaS sections

Projects must be visually dominant.

Use large project imagery and create dedicated project case-study pages.

Each section should have its own composition while remaining part of one
coherent design system.

Use Motion for subtle interaction.
Use GSAP only where sophisticated scroll choreography genuinely improves
the experience.

Use custom components for the public-facing website rather than making the
site look like a component-library demo.

Treat desktop layouts like an editorial publication.
Treat mobile as a separately considered responsive experience.

Before implementation:
1. Establish typography.
2. Establish grid.
3. Establish spacing system.
4. Establish color system.
5. Establish image treatment.
6. Establish motion principles.

After implementation:
1. Browser-test at desktop, tablet and mobile sizes.
2. Check visual hierarchy.
3. Remove anything that looks generic or templated.
4. Verify accessibility.
5. Verify performance.
6. Refine spacing, typography and imagery before considering the design
   complete.

The final experience should feel engineered rather than decorated.
```

---

# 35. Final Design Standard

The final website should make visitors think:

> **This company is technically serious, established, precise and capable of handling major projects.**

It should not make visitors think:

> **This is another website generated from a generic modern landing-page template.**

When in doubt, choose:

**Less decoration. Better typography. Better imagery. Better spacing. Better structure.**
